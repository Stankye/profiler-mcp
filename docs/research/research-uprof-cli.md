# uprof-cli

## Summary
AMD uProf is AMD's performance-analysis suite; its CLI is **AMDuProfCLI** (subcommands: collect, translate, report, profile, diff/compare, timechart, info). Current release is uProf 5.2 (Dec 11, 2025); the docs portal (document 57368, docs.amd.com) tracks 5.1/5.2, and the last fully downloadable PDF I verified verbatim is Rev 4.2 (Jan 2024). Workflow: `collect` launches or attaches to a program and writes raw data (.caperf on Linux, .prd on Windows, .pdata on FreeBSD) into a timestamped session dir `AMDuProf-<APP>-<CONFIG>_<Mon-DD-YYYY_hh-mm-ss>/` under the `-o/--output-dir` base dir; `translate` converts raw files into .db database files (importable by GUI/CLI); `report` does translate+report in one step and emits a CSV report (report.csv) with fixed sections (EXECUTION, PROFILE DETAILS, MONITORED EVENTS, 10 HOTTEST FUNCTIONS, TAKEN BRANCH ANALYSIS SUMMARY, 10 HOTTEST PROCESSES/MODULES/THREADS, and with --detail per-process THREAD/MODULE/FUNCTION SUMMARY, function detail with source lines, CALLGRAPH). Note the AMDuProfCLI report format is CSV only — there is no `-f csv` on it; `-f/--format {txt,csv}` belongs to `timechart` (and a separate tool, AMDuProfSys, has its own same-named collect/report commands with `-f csv|xls` and `-G system|package|numa|ccx`; do not confuse the two — the docs.amd.com slugs "Collect-Command"/"Report-Command" actually resolve to the AMDuProfSys pages).

**collect** key options (verified from Table 25/26/27 of Rev 4.2): `--config <name>` (repeatable; list via `AMDuProfCLI info --list collect-configs`) with predefined configs: tbp (time-based), assess, assess_ext, data_access, inst_access, branch, cpi, threading (Linux-only, Zen3/Zen4), ibs, memory (false-sharing via IBS OP), energy (power sampling, shown for Windows), gpu (Linux+ROCm), plus 5.0+ additions `hotspots` (inclusive/exclusive time hotspots incl. Java/Python on Linux) and `overview` (MI300A heterogeneous). `-e/--event` takes either a predefined event name or `key=value` pairs: event=<timer|ibs-fetch|ibs-op|PMU-event|predefined>, umask, user=0|1, os=0|1, cmask=0x0-0x7f, inv, interval (ms for timer; event count for PMC; fetch/cycle-dispatch count for IBS; defaults 1.0 ms timer / 250000 others), frequency (Hz, core PMC), ibsop-count-control, ibsop-l3miss/ibsfetch-l3miss (Zen4), call-graph. Other flags: `-p/--pid <PID,...>` attach (max 512), `--tid` (Linux), `-a/--system-wide`, `-c/--cpu 0-3`, `-d/--duration <s>`, `--interval <n>` (overrides per-event), `-F/--frequency <Hz>`, `--affinity 0-3`, `--start-delay <s>`, `--start-paused`, `--no-inherit`, `-b/--terminate`, `-w/--working-dir`, `--limit-size <MB>`, `-g` (callstacks; Linux `--call-graph <fp | fpo:N>` with N=stack bytes 16-32768 default 1024 dwarf unwind; Windows `--call-graph I:D:S:F` e.g. 1:64:user:fpo), logging (`--log-path`, `--enable-log`, `--enable-logts`, AMDUPROF_LOGDIR env). MPI: add `--mpi` under `mpirun` (raw data from all ranks lands in one session dir; report with `--host <hostname>|all`); MPI/OpenMP/OS/GPU tracing via `--trace mpi[=openmpi|mpich,lwt|full]`, `--trace openmp` (alias `--omp`), `--trace os[=syscall:1000,...]`, `--trace user=...`, `--trace gpu[=hip,hsa]`, with `--func`/`--exclude-func module:pattern` function tracing, `--buffer-size`, `--max-threads`, KVM guest flags (`--kvm-guest <pid>`, `--guest-kallsyms/modules/search-path`), and `--branch-filter [u,k,any,any_call,any_ret,ind_call,ind_jmp,cond,call]` for LBR capture.

**report** key options (Table 28/29/30): `-i/--input-dir <session-dir>` (accepts raw or translated session), `--report-output <path>` (if path ends in .csv it is the file, else treated as a directory and default-named report is written there), `--stdout`, `--detail`, `--group-by <process|module|thread>` (only with --detail; default process), `-p/--pid` filter, `-g` (callgraph), `--cutoff <n>` (default 10), `--view <view-config>` (e.g. ipc_assess, triage_assess, br_assess, dc_assess, misalign_assess; list via `info --list view-configs`), `-s/--sort-by event=<timer|ibs-fetch|ibs-op|pmcxNNN>[,umask=,user=,os=,cmask=,inv=]`, `--time-filter T1:T2`, `--agg-interval <low|medium|high|ms>`, `--imix`, `--inline` (Linux only), `--show-sys-src`, `--src-path`/`--bin-path`/`--symbol-path` (semicolon-separated, repeatable), `--disasm`/`--disasm-only`/`--disasm-style att|intel`, `--ignore-system-module`, `--show-percentage`/`--show-sample-count`/`--show-event-count`, `--show-all-cachelines`, `--retranslate`, `--remove-raw-files`, `--export-session`; Linux-only `--host <hostname|all>`, `--category cpu,mpi,openmp,trace,gputrace,gpuprof`, `--funccount-interval`; Windows-only `--symbol-server`, `--symbol-cache-dir`, `--legacy-symbol-downloader`. There is also a one-shot `profile` command (`AMDuProfCLI profile --config tbp -o dir app` = collect+report) and `diff`/`compare` for session comparison (`--baseline`, `--with`, `--type name|order`, markdown output).

**timechart** (power/thermal/frequency; Windows+Linux only): `-e/--event <device and/or category>` where devices are socket, die, core, thread (e.g. `core=0-3,frequency`) and categories are power, frequency, temperature, voltage, current, dvfs, energy, cac, controllers (enumerate with `AMDuProfCLI timechart --list`; the set is family-specific); `-t/--interval <ms>` (minimum 10 ms), `-d/--duration <s>`, `-o/--output-dir`, `-f/--format txt|csv` (default csv), `--affinity`, `-w`. **info**: `--system` (processor info), `--list collect-configs|predefined-events|pmu-events|cacheline-events|view-configs` (+ Linux: `trace-events`, `gpu-events`), `--collect-config <name>`, `--view-config <name>`, `--pmu-event pmcx76`, `--bpf` (Linux BPF/BCC support check). **Platforms**: Windows 10/11 + Server 2019/2022, Linux (Ubuntu 16.04+, RHEL/CentOS 7+, openSUSE Leap 15, SLES 12/15), FreeBSD 12.2+ (CLI only, no timechart); CPUs: AMD "Zen"-based CPUs/APUs full-featured; **Intel processors are supported for time-based profiling only** (no EBP/PMC, no IBS, no power profiling); Instinct MI100/MI200 (+MI300A in 5.x) for GPU trace/profile via ROCm. **Install**: Linux tar/rpm/deb → `/opt/AMDuProf_X.Y-ZZZ/` (binaries in `bin/`, e.g. `/opt/AMDuProf_X.Y-ZZZ/bin/AMDuProfCLI`), Windows → `C:\Program Files\AMD\AMDuProf\`. Power profiling (timechart / energy config) requires the AMDPowerProfiler kernel driver: auto-installed by rpm/deb, manual `sudo ./AMDPowerProfilerDriver.sh install` for tar installs (DKMS supported; source lands in /usr/src/AMDPowerProfiler-<version>, MIT license). CPU profiling on Linux rides on perf_event: per-process TBP/EBP works with perf_event_paranoid up to 2, kernel/hypervisor scope needs ≤1, system-wide needs ≤0, and IBS needs ≤0 (docs commonly instruct `sysctl -w kernel.perf_event_paranoid=-1`); kernel symbol attribution additionally wants kptr_restrict=0. The msr module (`modprobe msr`) and disabled NMI watchdog are prerequisites for the companion AMDuProfPcm tool (`--msr` mode), not for AMDuProfCLI sampling. Docker profiling needs `--cap-add=CAP_SYS_ADMIN`. **Exit codes are not documented anywhere in the user guide**; observed behavior is 0 on success and non-zero (e.g. 255) on errors — an automation layer should treat exit!=0 as failure, capture stderr, and verify that the timestamped session directory (collect) or report.csv (report) actually exists; also note collect prints the generated session path on stdout, and `AMDuProfCLI --version` is available for version probing.

## Key facts
- Current release: AMD uProf 5.2 (2025-12-11); docs portal document ID 57368 tracks 5.1/5.2; last verbatim-verified PDF is User Guide Rev 4.2 (Jan 2024, publication 57368)
- AMDuProfCLI subcommands: collect, translate, report, profile (collect+report one-shot), diff/compare, timechart, info
- --config values: tbp, assess, assess_ext, data_access, inst_access, branch, cpi, threading (Linux-only, Zen3/Zen4), ibs, memory, energy, gpu; 5.0 added hotspots (callstack time hotspots, C/C++/Java/Python on Linux) and overview (MI300A); enumerate at runtime with 'AMDuProfCLI info --list collect-configs'; multiple --config allowed in one run
- -e/--event syntax: event=<timer|ibs-fetch|ibs-op|pmcxNNN|PREDEFINED>,umask=,user=0|1,os=0|1,cmask=0x0-0x7f,inv=,interval=,frequency=<Hz>,ibsop-count-control=,ibsop-l3miss,ibsfetch-l3miss,call-graph; defaults interval=1.0ms (timer) / 250000 (PMC & IBS)
- Attach: -p|--pid <PID,...> (max 512 processes), Linux-only --tid <TID,...>; -a|--system-wide for SWP; -d|--duration <sec>; --start-delay <sec>; --start-paused (needs AMDProfileControl API instrumentation); -c|--cpu and --affinity take comma lists/ranges like 0-3
- Callstacks: -g; Linux --call-graph <fp|fpo:N> (fpo=dwarf, N=16-32768 bytes, default 1024); Windows --call-graph I:D:S:F e.g. 1:64:user:fpo
- MPI: run under mpirun with --mpi flag (CPU profiling) or --trace mpi[=openmpi|mpich,<lwt|full>] (tracing; default mpich,full); OpenMP: --omp or --trace openmp; report per-host with Linux-only --host <hostname|all> and --category cpu,mpi,openmp,trace,gputrace,gpuprof
- Raw data formats: .caperf (Linux), .prd (Windows), .pdata (FreeBSD) inside session dir named AMDuProf-<APP>-<CONFIG>_<Mon-DD-YYYY_hh-mm-ss>; translate produces .db database files; report produces CSV (report.csv)
- report has NO -f/--format flag (CSV only): --report-output <path> (path ending .csv = exact file, otherwise directory), --stdout prints to terminal; --group-by <process|module|thread> valid only with --detail (default process); filtering via --cutoff <n> (default 10), -p/--pid, --view <view-config>, -s/--sort-by event=..., --time-filter T1:T2, --ignore-system-module, --inline (Linux only), --src-path/--bin-path/--symbol-path
- timechart: -e/--event devices {socket, die, core, thread} + categories {power, frequency, temperature, voltage, current, dvfs, energy, cac, controllers} (family-specific; list with 'timechart --list'); -t/--interval <ms> min 10ms; -d/--duration <sec>; -f txt|csv default csv; Windows+Linux only (no FreeBSD)
- info: --system, --list {collect-configs, predefined-events, pmu-events, cacheline-events, view-configs} (+Linux: trace-events, gpu-events), --collect-config <name>, --view-config <name>, --pmu-event pmcx76, --bpf (Linux)
- CPU support: AMD Zen-based CPUs/APUs full feature set; Intel processors = time-based profiling (tbp) ONLY - no PMC/EBP, no IBS, no power profiling; GPU profiling needs AMD Instinct MI100/MI200/MI300A + ROCm
- Install paths: Linux /opt/AMDuProf_X.Y-ZZZ/ (CLI at bin/AMDuProfCLI), Windows C:\Program Files\AMD\AMDuProf\; Linux packages: amduprof-x.y-z.x86_64.rpm, amduprof_x.y-z_amd64.deb, AMDuProf_Linux_x64_x.y.z.tar.bz2
- Power driver: AMDPowerProfilerDriver.sh install (manual only for tar installs; rpm/deb auto-install; DKMS supported; source in /usr/src/AMDPowerProfiler-<version>, MIT-licensed) - required for timechart/energy on Linux
- Linux perf_event_paranoid requirements (Table 47): per-process TBP/EBP works at value 2; kernel/hypervisor scope needs <=1; system-wide (-a) needs <=0; IBS (any scope) needs <=0; docs recommend setting -1; kernel symbols also need kptr_restrict=0; msr module + NMI-watchdog-off are for AMDuProfPcm, not AMDuProfCLI
- Exit codes are NOT documented in the user guide; observed: 0 success, non-zero (e.g. 255) on error - automation should check exit status plus existence of session dir / report.csv, and parse the session path collect prints on stdout
- Report CSV sections: EXECUTION, PROFILE DETAILS, MONITORED EVENTS, 10 HOTTEST FUNCTIONS, TAKEN BRANCH ANALYSIS SUMMARY, 10 HOTTEST PROCESSES/MODULES/THREADS; with --detail adds per-process THREAD/MODULE/FUNCTION SUMMARY, source-level function detail, CALLGRAPH
- Container: profiling inside Docker requires --cap-add=CAP_SYS_ADMIN; from outside attach via --pid and pass --bin-path/--src-path at report time; virtualization supported on VMware ESXi, KVM (--kvm-guest <pid> + --guest-kallsyms/--guest-modules/--guest-search-path), Xen, Hyper-V

## Example commands
    AMDuProfCLI info --list collect-configs
    AMDuProfCLI info --system
    AMDuProfCLI.exe info --collect-config assess_ext
    AMDuProfCLI.exe info --pmu-event pmcx76
    ./AMDuProfCLI collect -o /tmp/cpuprof-tbp AMDTClassicMatMul-bin
    ./AMDuProfCLI collect --config assess -o /tmp/cpuprof-assess -d 10 AMDTClassicMatMul-bin
    ./AMDuProfCLI collect --config ibs -a -o /tmp/cpuprof-ibs-swp AMDTClassicMatMul-bin
    ./AMDuProfCLI collect --config tbp -g -o /tmp/cpuprof-tbp AMDTClassicMatMul-bin
    ./AMDuProfCLI collect --config tbp --call-graph fpo:512 -o /tmp/uprof-tbp AMDTClassicMatMul-bin
    AMDuProfCLI collect --config tbp -o /tmp/cpuprof-tbp-attach -d 10 --tid <TID>
    AMDuProfCLI collect --config memory -o /tmp/cpuprof-mem AMDTClassicMatMul-bin
    AMDuProfCLI collect --config threading -o /tmp/cpuprof-threading AMDTClassicMatMul-bin
    AMDuProfCLI collect --omp --config tbp -o /tmp/openmp_trace <path-to-openmp-exe>
    mpirun -np 4 ./AMDuProfCLI collect --config assess --mpi --output-dir /tmp/cpuprof-mpi /tmp/namd <parameters>
    mpirun -np 16 /tmp/AMDuProf/bin/AMDuProfCLI collect --config tbp --trace mpi --output-dir /tmp/myapp-perf myapp.exe
    ./AMDuProfCLI collect -e event=ibs-op,interval=50000 -o /tmp/cpuprof-tbp AMDTClassicMatMul-bin
    AMDuProfCLI collect -e event=RETIRED_INST,interval=250000 -e event=L1_DC_REFILLS.ALL,user=1,os=0,interval=250000 -o /tmp/cpuprof-pmc AMDTClassicMatMul-bin
    AMDuProfCLI collect --trace os=syscall:1000 -o /tmp/cpuprof-os AMDTClassicMatMul-bin
    AMDuProfCLI collect --trace os --func c:malloc,calloc,kernel:vfs_read* -o /tmp/cpuprof-os -a -d 10
    AMDuProfCLI collect --branch-filter -o /tmp/cpuprof-ebp-branch AMDTClassicMatMul-bin
    AMDuProfCLI report -i /tmp/cpuprof-tbp/<SESSION-DIR>
    AMDuProfCLI report -s event=ibs-op -i /tmp/cpuprof-ibs/<SESSION-DIR>
    AMDuProfCLI report --imix -i /tmp/cpuprof-imix/<SESSION-DIR>
    AMDuProfCLI report -i /tmp/cpuprof-os/<SESSION-DIR> --category trace
    AMDuProfCLI.exe report --view ipc_assess -i c:\Temp\pwrprof-swp\<SESSION-DIR>
    AMDuProfCLI.exe report --bin-path Examples\AMDTClassicMatMul\bin\ --src-path Examples\AMDTClassicMatMul\ -i c:\Temp\cpuprof-tbp\<SESSION-DIR>
    AMDuProfCLI translate -i /tmp/cpuprof-tbp/<SESSION-DIR>
    AMDuProfCLI profile --config tbp -o AMD_profile_output --affinity 1 ./AMDTClassicMatMul
    AMDuProfCLI diff --baseline /tmp/cpuprof-tbp/<BASE-DIR> --with /tmp/cpuprof-tbp/<NON-BASE-DIR> -o /tmp/cpuprof-tbp
    AMDuProfCLI timechart --list
    ./AMDuProfCLI timechart --event power --interval 100 --duration 10
    ./AMDuProfCLI timechart --event frequency -o /tmp/PowerOutput --interval 500 --duration 10
    ./AMDuProfCLI timechart --event core=0-3,frequency -o /tmp/PowerOutput --interval 500 --duration 10 --format txt
    AMDuProfCLI timechart --event core=0-3,power -o AMD_profile_output --interval 10 --affinity 1 ./AMDTClassicMatMul
    sudo sysctl -w kernel.perf_event_paranoid=-1
    sudo echo 0 > /proc/sys/kernel/kptr_restrict
    sudo ./AMDPowerProfilerDriver.sh install
    sudo rpm --install amduprof-x.y-z.x86_64.rpm
    AMDuProfCLI --version

## Caveats
- Option tables were verified verbatim against the Rev 4.2 PDF (Jan 2024); the live docs portal covers 5.1/5.2 and AMD's 5.0 release notes mention 'simplified CLI options', so a few flags may have shifted - always cross-check against `AMDuProfCLI <command> --help` and `info --list collect-configs` on the installed version at runtime
- Name collision hazard: the suite also ships AMDuProfSys (python system-analysis tool) and AMDuProfPcm; AMDuProfSys has its OWN collect/report commands with different flags (-f csv|xls, -G system|package|numa|ccx, .ses session files) - the docs.amd.com slugs 'Collect-Command' and 'Report-Command' resolve to the AMDuProfSys pages, not AMDuProfCLI; do not mix their flag sets
- AMDuProfCLI report emits CSV only - the '-f csv' and '--group-by' semantics the task asked about partially belong to other commands: -f/--format {txt,csv} is a timechart option; report's --group-by only accepts process|module|thread and only works together with --detail
- Exit codes / scripting contract are completely undocumented in the official guide; automation must rely on exit!=0 + stderr + verifying session-dir/report.csv existence
- The predefined-config list is family/model-dependent (e.g. threading only on Linux Zen3/Zen4; ibsop-l3miss/ibsfetch-l3miss only Zen4; hotspots/overview only 5.0+; energy config shown on Windows) - enumerate per-host rather than hardcoding
- On Intel CPUs only tbp works (timer-based via OS APIs); EBP/PMC, IBS, memory/branch/cpi configs and timechart power profiling all require AMD hardware; timechart additionally requires the AMDPowerProfiler kernel driver on Linux and is unavailable on FreeBSD
- The 4.2 PDF renders the actual `info --list collect-configs` and `timechart --list` outputs as screenshots (Figures 30-33), so the exact per-platform config/counter lists could not be transcribed from the PDF - the timechart device/category lists here come from the 3.4 guide text and may have grown since
- perf_event_paranoid guidance differs by scope: per-process TBP/EBP tolerates the Ubuntu default (2), but IBS and system-wide need <=0; HPC sites (e.g. SURF Snellius) gate this behind special job flags - an automation layer should probe /proc/sys/kernel/perf_event_paranoid and degrade gracefully
- Session directory name contains app name, config and a timestamp (AMDuProf-<APP>-<CONFIG>_<Mon-DD-YYYY_hh-mm-ss>), so scripts must capture collect's stdout or glob for the newest subdirectory rather than predicting the path
- docs.amd.com pages are JS-heavy and were fetched via a summarizing model; low-level details from those fetches (as opposed to the PDFs I parsed directly) carry slightly lower confidence
